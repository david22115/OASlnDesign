# 功能規格明細 (Functional Requirements Specification)
**文件版本**：v1.2 | **日期**：2026-04-08 | **狀態**：✅ SA 架構師確認 / ✅ 資深 SE 可行性審核通過

---

## 一、文件範疇 (Scope)

本文件定義本次企業 OA 系統開發所需實作的**全部功能需求明細**，作為前後端工程師開發、QA 測試驗收的基準依據。
所有功能均已納入七項架構優化設計，確保系統在可維護性、安全性、效能與擴充性上符合企業生產等級標準。

---

## 二、使用者角色 (Actors)

| 角色代碼 | 名稱 | 說明 |
|---------|------|------|
| `ADMIN` | 系統管理員 | 全系統最高權限，管理帳號、角色與組織 |
| `MANAGER` | 主管 | 可審核、催辦、查閱部門員工資訊 |
| `EMPLOYEE` | 一般員工 | 使用系統標準功能 |
| `GUEST` | 外部訪客 / 約聘 | 無帳密，透過 OTP / QR Code 登入，最低權限 |
| `KIOSK` | 廠區終端裝置 | UUID 設備綁定，僅供打卡使用 |

## 三、功能模組需求明細

### 📌 FR-01：單一登入入口 (SSO / EIP Portal)

| 需求 ID | 功能名稱 | 優先級 | 說明 |
|---------|---------|--------|------|
| FR-01-01 | 帳密登入 | P0 | 串接 AD/LDAP 或內部帳號庫，驗證成功後派發 JWT (Access + Refresh Token) |
| FR-01-02 | OTP 無密碼登入 | P0 | 透過 Email 或 SMS 發送六位數一次性驗證碼登入 |
| FR-01-03 | QR Code 掃碼登入 | P1 | Web 端顯示動態 QR Code，由行動 App 掃描後完成授權 |
| FR-01-04 | 設備 UUID 訪客登入 | P1 | 廠區設備或約聘人員，以裝置 UUID 換取最低權限訪客 Token |
| FR-01-05 | MFA 多因素驗證 | P0 | 高權限角色 (ADMIN / MANAGER) 強制啟用 MFA（Google Authenticator / SMS） |
| FR-01-06 | JWT Token 黑名單機制 | P0 | 登出或離職異動觸發時，將 Token `jti` 寫入 Redis 黑名單即時生效 |
| FR-01-07 | Launchpad 動態應用程式清單 | P0 | 登入後依使用者角色與 AccessPolicy 動態渲染有權限的子系統圖示 |
| FR-01-08 | 子系統 SSO 跳轉 | P0 | 點擊子系統圖示後，透過 OIDC/SAML 或代填機制實現無縫跳轉，無需二次登入 |
| FR-01-09 | Legacy 系統反向代理跳轉 | P1 | 對舊 ASP/JSP 系統，BFF 後端代填登入並注入 Session Cookie 後導向 |
| FR-01-10 | 個人化桌面釘選排序 | P2 | 允許使用者自行釘選、拖曳排序常用系統圖示 |

| 需求 ID | 功能名稱 | 優先級 | 說明 |

### 📌 FR-08：全域稽核與資安 (Security & Audit)

| 需求 ID | 功能名稱 | 優先級 | 說明 |
|---------|---------|--------|------|
| FR-08-01 | 一致性稽核日誌 | P0 | 所有透過 AccessPolicy Engine 放行的操作，非同步寫入 `SystemAuditLog`（含 IP、UserAgent、資源類型） |

## 四、非功能性需求 (Non-Functional Requirements)

| 類別 | 需求 | 目標值 |
|------|------|--------|
| 效能 | 一般 API 回應時間 | P95 < 300ms |
| 效能 | 打卡高峰期並發量 (09:00) | 支援 500 req/sec，系統回應正常 |
| 可用性 | 系統可用性 | 99.5% Uptime |
| 資安 | 滲透測試 | 每季執行一次 OWASP Top 10 審核 |
| 擴充性 | Serverless 水平擴充 | 服務層設計支援 PgBouncer / Prisma Accelerate 連線池管理 |
| 法規 | 個人資料保護 | 符合 PDPA / 台灣個資法要求，PII 欄位加密存放 |
